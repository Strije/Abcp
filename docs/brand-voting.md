# Автовыбор бренда голосованием поставщиков

Человек ищет номер (162622, W71295, OC90), ABCP отдаёт несколько брендов, и все «в наличии».
Раньше приложение в этом случае всегда показывало список. Теперь бренд, который продаёт явное
большинство поставщиков, открывается сразу — как в Pricer (веб-версия «Проценки»,
[github.com/Strije/Pricer](https://github.com/Strije/Pricer): `engine.search_brands` + `app/search.py choose_brand`).

Где лежит:

| Где | Файл |
|---|---|
| приложение (Kotlin) | `app/src/main/java/com/example/myapplication/abcp/BrandVoting.kt`, вызов — `SearchActivity.search()`, запросы — `AbcpShop.brandVoting()` |
| сервер (Python) — для подбора и всего серверного | `server/app/brand_vote.py` |
| тесты | `app/src/test/.../BrandVotingTest.kt`, `server/tests/test_brand_vote.py` — одни и те же случаи |

## Правило

1. **Сначала старые правила приложения** (`autoPickBrand`): бренд один; бренд известен заранее
   (подбор по VIN/ТО передаёт его); в наличии только один. Если сработало — голосование не нужно.
2. **Голос** бренда — сколько **разных поставщиков** продают именно этот номер этого бренда.
   Считается по ответам `search/articles` (номер + бренд) для первых 6 брендов списка, запросы параллельные.
   - В ответе бывают аналоги — в зачёт идут только предложения с тем же номером (`number` или `numberFix`
     после очистки) и брендом группы. Одно предложение, пришедшее в двух ответах, считается один раз.
   - Поставщик — как у ★: `distributorId`, иначе `supplierCode`. Склады самовывоза АвтоДруг (срок 0 и
     «самовывоз» в подписи срока) — один поставщик.
   - Гость: сервер не отдаёт поставщиков, зато считает ★ (`confirmCount`) — голос берётся из неё.
3. **Один бренд — разные строки ABCP.** «MANN-FILTER (China)» и «MANN-FILTER» (и «MANN») — одна группа:
   ключ без уточнения в скобках, без знаков и с теми же синонимами, что у ★ (`BRAND_ALIASES`).
   Голоса группы складываются, открывается строка, под которой больше поставщиков.
4. **Упоминания.** Аналоги пишут настоящего производителя в названии («Фильтр масляный [ан. MAHLE OC90]»).
   Каждое такое предложение другого бренда — ещё +1 к бренду. Ищется бренд целиком и части через «/»
   («Mahle/Knecht» — и MAHLE, и KNECHT), слово от 3 букв, целым словом.
5. **Решение.** Сортировка по «голоса + упоминания», при равенстве — по голосам, затем порядок ABCP.
   Лидера открываем сразу, если:
   - у него **не меньше половины** ответивших поставщиков (ответившие — разные поставщики во всех
     предложениях с этим номером; у гостя — сумма голосов, так набрать большинство труднее), и
   - его «голоса + упоминания» **в 1,5 раза больше**, чем у второго (у второго не меньше 0,5).

   Иначе показываем список — уже по числу поставщиков, с подписью «у N поставщиков».
   Выбранный автоматически бренд можно сменить: «Назад» возвращает к списку.

Пороги 0,5 и 1,5 — те же, что в Pricer. Там их проверили на записи ответов 12 поставщиков 02.10.2026:
162622 — ZIC у 6 из 12, у остальных 1–2 — берём ZIC; W71295 — MANN 7 голосов и 2 упоминания против
Redskin 4 — берём MANN; OC90 — MAHLE 7 и 2 упоминания против AM POINT 7 — спрашиваем.

## Чем отличается от десктопа и Pricer

- **Десктоп** берёт бренд сам, только если вариант один, иначе всегда спрашивает.
- **Pricer** голосует поставщиками: каждый из 12 сам называет бренды для номера.
- **ABCP** отдаёт один общий список без разбивки, поэтому голос здесь — число поставщиков в предложениях.
  Цена — до 6 запросов `search/articles` на неоднозначный поиск. Однозначные (один бренд, известный
  бренд, единственный в наличии) обходятся без них, как раньше.

## Как подключить в подборе (сервер)

```python
from app.brand_vote import pick_brand, vote_for_number

voting = await vote_for_number(number, brand_rows,           # brand_rows — ответ search/brands
                               fetch=lambda brand: guest_offers(a, number, brand, profile_id, False))
row = pick_brand(voting)    # строка search/brands, которую брать; None — бренд неоднозначен
# voting["votes"]: [{"row", "brand", "votes", "mentions", "score"}, ...] — лучшие сверху
```

Если предложения уже получены — `vote_brands(number, brand_rows, {бренд: строки search/articles})`
считает то же без запросов. Пороги — параметры `pick_brand(voting, share=0.5, lead=1.5)`.
