# Робот подбора — правила для правок

VIN + сумбурный текст клиента → детали Laximo + цены ABCP. План и цифры — [docs/ROADMAP.md](../../../docs/ROADMAP.md),
раздел «Робот подбора». Отвечать пользователю по-русски, простыми словами.

## Чего робот не делает никогда

- **Номера — только из Laximo и ABCP.** Сами не придумываем; модель номеров не называет.
- **Закупочные цены (priceIn) и данные клиентов** никуда не отдаём и не пишем в журнал. Модели — только текст после
  `understand.mask` (без телефонов и VIN).
- **Позицию без вариантов клиенту не показываем** как найденную: «не нашли» или «передали менеджеру» — честно.
- **Чужую деталь хуже показать, чем передать менеджеру.** «Не нашли» нельзя снижать ценой мусора.
- **Ошибка каталога — `catalog_error`, а не падение.** Запасные пути (узлы, модель) при сбое возвращают «не нашли».
- **Сторону проверяем** по каталогу и по описаниям поставщиков; показываем её, только когда она что-то значит.

## Как устроено (где что лежит)

- `engine.py` — разбор просьбы и поиск: правила → быстрые группы (`TreeIndex`) → узлы полного каталога
  (`_by_units`, `_by_unit_part`, `_by_units_llm`, `_subframe`) → варианты и цены; арбитр-модель (`_arbitrate`) для слабых
  результатов; `draft()` — текст клиенту. Позиции с `via_units` / `settled` арбитр не трогает.
- `dialog.py` — продолжение разговора: память (`remember`, `_slim`), выбор варианта, «да» на вопрос робота.
- `understand.py` — запросы к модели и подсказки (prompt'ы).
- `catalog.py` — Laximo: деревья, детали, узлы, кэш на диске. `unit_file()` — по ssd узла (у части марок unitId «0»).
- `schemes.py` — картинки схем через наш сервер (короткий номер, адрес Laximo с учёткой — только у нас).
- `makes.py` — марка в словах ≠ марка по VIN → спрашиваем «для какой машины?».
- Данные: `data/podbor_rules.json` (синонимы, стоп-слова), `data/podbor_typos.json`, `text._SHORT`.

## Когда правка считается улучшением

Правка — это код, `podbor_rules.json`, `podbor_typos.json`, `text._SHORT` или пороги. Принимаем, только если:
1. все сценарии, что были зелёными, — зелёные;
2. на эталоне лаборатории верных не меньше, ошибок не больше; **новый провал — разбор**, даже если итог вырос;
3. на замере 300 переписок «не та деталь» не выросла;
4. после запуска у клиентов доля «клиент выбрал показанное» не упала.

Пункты 1–2 — одна команда на сервере (около 45 минут, итог в `REPORT.txt`):

    bash /srv/podbor-lab/repo/server/lab/rules_check.sh <ветка>

## Как работать

- Всё — в ветку; в `main` и в бой — только после «да» пользователя, зелёных Actions («Server tests») и проверки.
  Выкладка: `ssh root@109.73.199.217 "cd /opt/avtodrug-api/deploy; bash setup.sh update"`.
- Тесты: `cd server && python -m pytest -q`; разговор из консоли: `python -m app.podbor.talk "VIN реплика|реплика"`.
- Чинить общими правилами, а не под одну фразу; у каждой правки — тест с настоящей фразой клиента (без VIN).
- Клиентские данные (VIN, переписка, `scenarios_local.json`, `garage.jsonl`, журналы прогонов) — **не в git**,
  репозиторий публичный. Файлы добавлять по имени и смотреть `git status`.
- Лабораторные прогоны на сервере от root пишут в `STATE_DIR` (`/var/lib/avtodrug-api`) — новые папки там получаются
  root-овыми, и служба туда не пишет. После таких прогонов: `find /var/lib/avtodrug-api -user root`.
- Laximo — 600 запросов в минуту на весь сервис, общий с боевым роботом: массовые закачки с паузой.
- Python-строки с `\n` не править через heredoc в Bash — только инструментом правки файлов.
